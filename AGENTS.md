# gen-asyncapi

Generates Go or TypeScript from AsyncAPI 3 specs. If you only want to use the generator from an agent, read [.agents/skills/gen-asyncapi/SKILL.md](.agents/skills/gen-asyncapi/SKILL.md) instead; this file is about changing the code.

## Architecture

- `cmd/gen-asyncapi`: the CLI. Parses `--config`, `-language`, `-package`, `-o` and the spec path, applies flag overrides to the config, validates it, and writes the output file.
- `internal/codegen`: the generator. `config.go` loads and validates the YAML config. `builder.go` and `schema.go` turn schemas into an in-memory model (`model.go`: declarations, type references, checks). `generate.go` builds messages, servers, channels and operations and picks the renderer. `render.go` plus `templates/file.tmpl` write Go; `typescript.go`, `tscheck.go`, `templates/typescript.tmpl` and `templates/runtime.ts` write TypeScript.
- `asyncapirt`: runtime the generated Go imports: validation checks, strict object decoding, message matching, `Send`, the `Transport` interface.
- `asyncapirt/gorillaws`: a `Transport` over gorilla/websocket.
- Spec loading comes from `github.com/psyb0t/go-asyncapi`, a separate module.

Data flow: spec → `asyncapi.Load` → `builder` model → Go template or TypeScript renderer → one output file.

## Stack

- Go 1.26.9. Errors: `ctxerrors` wrapping `commerr` sentinels. Logging (CLI only): `slog` configured by `slogging/slogconf`, logger from `ctxscope.GetLogger(ctx)`.
- TypeScript checks: `tsc` 7 and Node.js 24 in the dev image, locked in `pnpm-lock.yaml`; tests use `node:test`.

## Layout

- `examples/chat`, `examples/shapes`, `examples/kitchensink`: specs, committed Go and TypeScript output, and Go and TypeScript tests against that output.
- `examples/official/*`: the 19 upstream AsyncAPI examples, generated in both languages; the specs are byte-for-byte upstream (Apache 2.0).
- `docs/spec-coverage.md`: what happens to each AsyncAPI object and schema keyword.
- `scripts/`: lint, coverage, TypeScript test and security scan scripts the Makefile runs.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

```bash
make generate       # regenerate every example (Go and TypeScript)
make lint           # shellcheck, shfmt, go fix, golangci-lint
make test-coverage  # go test -race with a 90% gate, then make test-ts
make test-ts        # tsc on the generated TypeScript, then node:test suites
make sec            # gitleaks, govulncheck, pnpm audit, semgrep
```

## Project-specific landmines

- Never hand-edit `*.gen.go` or `*.gen.ts`. `TestGeneratedExamplesAreCurrent` regenerates every `go:generate` line and fails on any difference, so a generator change always ships with regenerated examples.
- The generated TypeScript must keep passing the strict `tsconfig.json`, which checks it without Node.js types. Runtime helpers in `templates/runtime.ts` are only emitted when the generated code calls them, through the `//@rt <name>` markers; a helper without a marker never ships.
- Both languages share one model. A builder change shows up in both outputs; check both.
